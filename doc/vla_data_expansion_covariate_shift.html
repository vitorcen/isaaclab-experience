调研报告 RESEARCH 2026-06-03

为什么 ACT 学生 0.5 秒就摔，以及怎么治：covariate shift 与高质量数据扩充

Fixing the balance collapse in MimicKit→VLA distillation — covariate shift, recovery data, and the WBC route
三模型并行调研：Claude Opus 4.8 · GPT-5.5 (codex) · MiMo v2.5 Pro
TL;DR · 学生摔倒不是模型问题，是数据「分布」问题（covariate shift）。 三个模型独立调研高度一致：纯堆「干净数据」或「更大模型」都不治本，必须主动制造「快摔→teacher 拉回」的恢复态。

两条治本路（互补，不互斥）： ① 数据侧 —— DART（录制时给 teacher 动作注入噪声）→ 1-3 轮 DAgger，全程用免费的 PPO teacher 标注。便宜、沿用现有 ACT 管线、半天能判 go/pivot。 ② 架构侧 —— 用 NVIDIA GEAR-SONIC 全身控制器（WBC）当平衡底座，VLA 只出高层 latent，平衡 by construction 不摔，天花板更高但需引入 GEAR-SONIC + GR00T 栈。

铁律（文献支撑）： 公开 humanoid 全身控制工作里 没有一个靠纯离线 BC 成功 —— 都用了 RSI / online teacher query(DAgger) / RL fine-tune / 真人 teleop 恢复中至少一种。我们的负面结果是预期且解法 charted 的。

1. 问题复盘 The diagnosed failure

把 MimicKit DeepMimic PPO（G1，29-DoF，30Hz 闭环）蒸馏成 ACT 学生，闭环里 15-24 帧（0.5-0.8s）必摔（teacher 同起点跑满 300 帧）。诊断结论：

  • ✅ 任务条件化成立（fight/dance 动作分离比 3.84，无 mode collapse）—— 模型能表达、能区分，不是容量问题。
  • ✅ n_action_steps 16→1 几乎无差 —— 不是 open-loop horizon 问题。
  • ✅ train loss→0.149（拟合很死）—— 模型把给的数据学透了，数据本身不含恢复态。
根因 = covariate shift（协变量漂移）。 Teacher 是反应式闭环，访问过很宽的状态盆地；但录的数据只是它成功时走过的细轨迹管（它很少漂出去，所以数据里没有恢复样本）。学生一个小误差 → 漂出管 → 进入数据没覆盖的态 → 无恢复动作可学 → 误差二次累积（Ross & Bagnell 2010，BC error O(εT²)）→ 摔。

2. 方法谱系（三模型共识） Method spectrum

方法机制出处本 setup
DART（noise-injected BC） 录制时给 teacher 动作注入噪声 a_exec = teacher(s)+ε，但 label 存 teacher(s)；噪声把机器人推离轨迹，teacher 自然示范恢复。一次性、离线、不需在线交互。 Laskey et al., DART: Noise Injection for Robust Imitation Learning, CoRL 2017 🟢 必做·最高 ROI
DAgger 学生闭环跑、访问自己的状态分布，每个 state 查 teacher 要 label，聚合重训，迭代 2-3 轮。把 O(εT²) 降到 O(εT)。 Ross, Gordon, Bagnell, A Reduction of Imitation Learning…to No-Regret Online Learning, AISTATS 2011 🟢 必做·第二步
RSI（reference/perturbed state init） 每 episode 从任意 phase + 小扰动初态 reset，teacher 从附近恢复。teacher 本来就在 RSI 下训的，天然能处理。免费增量。 Peng et al., DeepMimic, SIGGRAPH 2018（teacher 的基础方法） 🟢 免费做
SafeDAgger / EnsembleDAgger 用 safety classifier / ensemble 方差只在「危险/不确定」处查 teacher，省查询。我们 teacher 免费 → query-efficiency 非核心，但可借其思想筛选高价值帧（root tilt 大、teacher-student action gap 大）。 Zhang & Cho 2017；Menda et al. 2019 🟡 借鉴筛选
HG-DAggerhuman-gated，靠人决定何时切换。我们 teacher 是自动 PPO → 改成自动 recovery gating（学生快摔时切 teacher 拉回并录）。 Kelly et al., ICRA 2019🟡 改自动
外力 push 扰动 rollout 中给 root 随机外力脉冲，teacher recover。覆盖 CoM/平衡恢复态。 OmniH2O（每 5s push, vxy≈1m/s）；DeepMimic（pelvis 0.2s push） 🟢 补充

3. 恢复态怎么造（具体参数） Generating recovery states

来源做法参数（三模型综合）
action-noise / DART a_exec = teacher(s) + N(0,σ) 喂 env；label 存 teacher(s)；下一步继续由 noisy teacher 控制。 扫 σ = 0.02 / 0.05 / 0.08 rad（≈1°/3°/4.6°）。选「teacher 300 帧存活率 ≥90% 但 root tilt/height 明显偏离」的最大 σ。σ>0.1 不试（humanoid 频繁摔，recovery label 变成「从地上爬」的大力矩，分布严重偏斜）。DART 原文：σ 应近似 learner error。
perturbed RSI reset 到任意 phase 的 reference state + 小扰动。免费，不增 episode。 joint pos ±0.02-0.05 rad，joint vel ±0.1-0.3 rad/s，root roll/pitch ±3-8°，root xy vel ±0.2-0.6 m/s。
push 扰动每 30-60 帧给 root 一次脉冲。 50-150N × 0.1-0.2s，或 velocity kick vxy=0.5-1.0 m/s，分层。
dynamics DR 随机物理参数，让学生见过不同 dynamics 下的恢复。 friction U(0.4,1.2)，mass U(0.8,1.2)，PD gain U(0.8,1.2)，control delay 0-2 frame。
auto recovery gating学生控制到风险阈值后切 teacher 1-2s，录 teacher 拉回段。 阈值：pelvis height 低于均值 10-15cm / root roll·pitch >12-18° / action L2 > p95。
关键判定：dynamics DR ≠ visual DR。 平衡是 dynamics 问题，dynamics DR（摩擦/质量/PD/延迟）才治；visual DR（光照/纹理）对 15-24 帧摔倒基本无用，只治视觉泛化。何况我们相机取景差（G1 占画面极小，类 π0.5 橙子瓶颈），vision 本就近乎噪声。 Dynamics DR for control, visual DR for perception — separate concerns (Miki et al., Science Robotics 2022).

4. ROI 排序 ROI ranking · 三模型一致

顺序铁律（两个外部模型都强调）：必须先 DART 再 DAgger。 裸 BC 直接跑 DAgger，学生第 1 秒就摔 → 采到的全是「快摔态」→ 数据集被恢复样本淹没、正常控制被稀释。先用 DART 把学生拉到 50+ 帧存活，DAgger 才能采到「有恢复力但偶尔漂移」的有价值数据。

6. 架构侧：GEAR-SONIC WBC 当平衡底座 The WBC route

用户提问：「能不能用会 G1 走路的 GR00T 当 base，再 fine-tune dance？」—— 答案是能，而且 NVIDIA 已经把这条路铺好了，这是 UNITREE_G1_SONIC embodiment。

为什么从构造上不摔：VLA 只出 latent（高层意图），平衡交给鲁棒的 WBC。VLA 的小误差 → 略不同的 latent → WBC 照样把机器人稳住。VLA 不需要学精细平衡。这正是 PULSE/ASE 的 latent-skill 范式被 NVIDIA 产品化。

已核实可用（web 核查）： nvidia/GEAR-SONIC（HuggingFace）是 G1 全身行为基础模型，会 walk/run/crawl/jump/manipulation；提供 MuJoCo sim demo、MotionBricks 键盘交互 viewer、`download_from_hf.py`、live web demo。GR00T 侧 UNITREE_G1_SONIC 是 posttrain tag（VLA 动作空间 = SONIC latent），需 finetune checkpoint。 来源：NVlabs/GR00T-WholeBodyControl、GEAR-SONIC VLA Workflow。

诚实的代价：① 需引入 GEAR-SONIC + GR00T 栈；② 动作空间变了（latent，非 29-DoF 关节）→ 现有 dataset 不能直接用；③ MimicKit teacher 出关节角，要把动作经 SONIC 重表示或用 GEAR-SONIC 自己的数据流程。

8. 陷阱与公开工作铁律 Pitfalls & prior art

8.1 看似有用实则不治本

做法为什么不治本
纯干净重放 ×10数据分布不变（同一细管），学生摔前 state 仍无 label
n_action_steps 16→1已验证无效；瓶颈不是 open-loop horizon
只加 visual DR不改 dynamics，proprio/control recovery 不会凭空出现
只堆参数 / 更大 VLA模型容量补不了缺失的 state-action 标签
σ 太大的 DART（>0.1 rad）humanoid 频繁摔，recovery label 变「从地上爬」的大力矩，分布偏斜，反而更糟
recovery 数据不做配比稀有恢复帧被 clean 帧淹没，loss 降但闭环不变

8.2 公开 humanoid 全身控制：数据怎么解决 covariate shift

工作怎么治 covariate shift
DeepMimic (2018)RSI + early termination + 外扰鲁棒性（不是纯 BC clean mocap）
OmniH2O (2024)privileged RL teacher → supervised distill + 大规模 retarget/DR/push；混合 RL recovery
HumanPlus (2024)真人 shadowing/teleop —— 人操作时天然含 OOD recovery（人帮机器人修正）
ExBody / ExBody2 (2024)RL teacher + 可行性过滤 + RSI + dynamics DR + 超大数据（10k+ ep）
PHC / PULSE (2022-24)RSI + teacher online query（本质 DAgger）；latent space + RL，不纯 BC
MaskedMimic (2024) / ASAP (2025)RL fine-tune + physics prior；BC warm-start 后用 RL polish
铁律：没有任何一个成功的 humanoid whole-body 工作是纯 offline BC。 全部至少用了：RSI / online teacher query(DAgger) / RL fine-tune / 真人 teleop 恢复 之一。数据规模典型 500-10k ep（我们 20 ep 是极端小）。dynamics DR 几乎必做。我们撞到的负面结果完全在文献预期内，解法是 charted 的。 Every successful humanoid whole-body work uses RSI / DAgger / RL-finetune / human-teleop recovery — never pure offline BC. Our negative result is expected; the fix is well-charted.

9. 三模型立场 Three-model synthesis

🟢 Claude Opus 4.8

框定为经典 imitation learning 问题（Ross&Bagnell O(εT²)），不是新难题。强调架构侧 SONIC WBC 路线（核实 nvidia/GEAR-SONIC 真实存在）作为「会走路的 base」的最强形态，与数据侧 DART/DAgger 互补。文献铁律：humanoid 全身无一靠纯离线 BC。

🔵 GPT-5.5 (codex)

逐方法核到一手文献（DAgger AISTATS'11 / DART CoRL'17 / OmniH2O / DeepMimic）。给出最细的恢复态参数表（σ 扫描、push 100-300N、RSI 噪声、dynamics DR 区间）+ 5-Phase pipeline + 失败 precursor 帧 oversample + recovery 帧 2× 加权、每 batch ≥30-50% 非 clean。明确 DceptionDAgger 无可核验出处、不纳入。

🟠 MiMo v2.5 Pro

给出最完整的公开 humanoid 工作对照表（PHC/OmniH2O/HumanPlus/ExBody/MaskedMimic/PULSE/ASAP/H2O 各自怎么治）+ 时间预算（P0-2 约 4h，含 P3 约 8h 出结论）+ go/no-go 阈值（mean≥50 进 DAgger，<35 查相机/state/scaling）。强调「先 DART 再 DAgger」的 curriculum 必要性。
