四模型并行调研：Claude Opus 4.7 · GPT-5.5 (codex) ✅ · DeepSeek V4 Pro ✅ · Xiaomi MiMo v2.5 Pro ❌ (tmux 崩溃)
TL;DR · 能做，但要正面承认局限。 MimicKit PPO 输出 29-DoF joint target 是 deterministic 的 state-based policy， 要变 VLA 训练集，关键是挂 RGB camera 录回放 + 语言 prompt per-episode + 转 LeRobot v2.1 格式。
Feasible but bounded. The bottleneck is not collecting data — it's that VLA student inherits SigLIP@224 perception, which struggles to distinguish "fight" vs "dance" from a single frame, and cannot reproduce the 60Hz dynamic balance that DeepMimic learned.

建议规模（codex 修正后）： 分 3 阶段： 50 → 200 → 500 ep/motion @ 30Hz（15s × 30Hz = 450 frame/ep）。 200 ep × 4 motion ≈ 360K frame 够判断通不通。MimicGen 不适用（全身 locomotion 没 object-centric 结构）， 用 RSI + DR + phase 随机化 + motor strength/PD/latency rand 平替。

第一个 student 不应该是 GR00T — 这本质是高频 control distillation，先用 ACT 或 Diffusion Policy + language embedding 验证 pipeline，GR00T/π0.5/SmolVLA 作 phase 2 对照（codex 强烈建议）。

第二轮评审修正（§7，Claude × GPT-5.4）： 基建优先于 expert —— 先补 recorder / modality.json / 第三人称 camera 跑激进 sanity， 再考虑加 dance expert（训多不训长，2-3 个验证 / 4-6 个才算 family coverage）。 最便宜的多样性杠杆是 prompt 侧多样化，DR ≠ semantic diversity。

1. 问题陈述 Problem Statement

当前已有：

  • 已 ship MimicKit DeepMimic G1 在 4 个 LAFAN motion family (fight/run/dance/jumps) 训练收敛 （15s 切段、Test_Return 200+、Test_Ep_Length 接近 ceiling）。
  • 每个 policy 是独立 PPO，obs ≈ proprio + ref motion phase + tar_obs，action = 29-DoF 关节目标。
  • 4 个 ckpt 各自训练，共享 hyperparam，但 prompt-driven 切换需要一个统一接口。

目标：

  • 把这 4 个 RL policy 蒸馏成一个 prompt-conditioned VLA（GR00T N1.7 / π0.5 / SmolVLA / X-VLA / ACT）。
  • 仿真里输入 "fight" / "run" / "dance" / "jump high" → 输出对应 motion。
  • 长期：加新 motion 时不重训 4 个 policy，而是 collect demo + finetune VLA。

3.1 数据格式：LeRobot v2 (GR00T-flavor) Format

codex 修正： GR00T 当前吃 LeRobot v2 + meta/modality.json，不是 v3。 parquet 必须含 annotation.human.action.task_description 字段。LeRobot v3 也可，但 GR00T trainer 还在跟。 π0.5 / SmolVLA / X-VLA / ACT 接 LeRobot v2 没问题。

结构（v2 + modality.json）：

my_g1_lafan_vla/
├── meta/
│   ├── info.json                     # schema: keys, dims, fps, robot_type
│   ├── tasks.jsonl                   # {task_index, task: "fight stance"}  × 4
│   ├── episodes.jsonl                # {episode_index, tasks: ["fight"], length: 900}
│   └── modality.json                 # GR00T 特有：state/action/video key 映射
├── data/
│   └── chunk-000/
│       └── episode_000000.parquet    # action, observation.state, timestamp, ...
└── videos/
    └── chunk-000/
        └── observation.images.front/
            └── episode_000000.mp4    # 224×224 @ 60Hz (或下采样 30Hz)

关键字段（每帧一行 parquet）：

列shape来源说明
action(29,)PPO output关节目标角度（zero_center, deg→rad 看模型）
observation.state(66+,)env29 joint pos + 29 joint vel + base ang vel(3) + projected gravity(3) + phase_sin/phase_cos + prev_action(29)。phase 是 codex 强调的关键 — 没它 VLA 不能从 RGB 推 timing。
annotation.human.action.task_descriptionint64—GR00T 必需字段，每帧重复 episode 的 task_index
observation.images.front(224,224,3)RGB camvideo 引用，parquet 只存 frame index
timestampscalarenv0.0 ~ 15.0
episode_indexint64—0..999
frame_indexint64—0..899 (60Hz × 15s)
task_indexint64—0=fight, 1=run, 2=dance, 3=jumps
Why parquet + mp4 分离：image 占 99% 字节，mp4 H.264 比 png 列存压缩 50-100×。 LeRobot 用 delta_timestamps 让 dataloader 按需 seek video 帧 — image 不进 parquet。 Storage: 1000 ep × 900 frames × 224² × 3 = 130 GB raw, ~3 GB after H.264 CRF 23.

3.2 怎么挂 camera Camera Setup

MimicKit 现成只有 /OmniverseKit_Persp viewport camera 录视频，per-env 训练 camera 要自己加：

from isaaclab.sensors import CameraCfg, TiledCameraCfg
import isaaclab.sim as sim_utils

# 在 isaac_lab_engine.py 的 scene 配置中加：
front_cam = TiledCameraCfg(
    prim_path="{ENV_REGEX_NS}/Robot/torso_link/front_cam",
    offset=CameraCfg.OffsetCfg(pos=(0.4, 0.0, 0.3), rot=(0.5, -0.5, 0.5, -0.5)),
    spawn=sim_utils.PinholeCameraCfg(
        focal_length=14.0, horizontal_aperture=20.955,
        clipping_range=(0.05, 50.0),
    ),
    width=224, height=224,
    data_types=["rgb"],
    update_period=1/30.0,   # 30Hz capture 够 VLA 用
)
Tiled camera 必须的： TiledCameraCfg 多 env 共享 GPU buffer，4096 env 4090 上才能跑； CameraCfg 单 env per-camera 是 OOM 配方。 For 1000 demos at 250 envs × 4 batches, TiledCamera@224 takes ~3GB extra VRAM.

视角选择 Camera viewpoint

  • 必须 第三人称侧视（2-3m back, 1.5m 高）：VLA 能看清全身姿态，"fight" 和 "dance" 视觉可分。
  • 推荐 头部第一人称（视线高度）：给 VLA 学 ego-centric 习惯，有助 sim-to-real。
  • 可选 俯视 top-down：debug 用，VLA 训练价值低。

codex 修正：原稿建议起步就 1000 ep 是 over-commit。staged 50 → 200 → 500 才对 — 50 ep 就能看出 pipeline 通不通，没必要烧钱跑 1000 ep 才发现 phase 没接好。
为什么 250 episode / motion 是起步：
  • PPO policy 是 deterministic（given seed），单 episode 多次重放无信息增益。
  • 有效多样性来自 RSI + domain rand（初始姿态 ±0.2m / ±15°，光照 3 mode，texture 2 类）。
  • 250 × 6 (RSI) × 3 (lighting) × 2 (texture) ≈ 9K 实际多样性单位，approximate π0 demos 数量级。
  • 4 个 motion × 250 ≈ Mason et al. 报告的 sweet spot for prompt-conditioned switching。

3.4 数据增强：MimicGen vs RSI vs DR Data Augmentation

方法适用本项目是否用理由
MimicGen（Mandlekar 2023）object-centric manipulation 不用 全身 locomotion 没有 object frame 可对齐；boxing/dance 不能 relative-to-object replay。
RSI (Reference State Init)RL motion tracking 标配 必用 DeepMimic 原文方案，从 motion clip 任意时刻 reset，免费拿到 phase 覆盖。
Domain Randomizationsim-to-real / VLA 视觉鲁棒 必用 texture / lighting / camera pose / shadow 随机；VLA 否则学到 sim-only artifact。
Action noise injectioncovariate shift 推荐 PPO output + N(0, 0.02) 让 VLA 学 recovery；不加的话 student 漂一点就崩。
Multi-clip per family语义泛化 推荐 同 "fight" prompt 用 5-10 个 LAFAN fight 切段训不同 expert；VLA 学到 family-level 语义而非 single clip overfit。
HumanoidGen / MotionLLM 类text → motion 合成 可选 需要先有 motion 库，跟 LAFAN ckpt 路径不同；后续扩展。

3.5 Prompt conditioning 怎么做 Language Conditioning

  • LeRobot v2.1 tasks.jsonl 每个 episode 关一个 task_index 和 free-form text。
  • GR00T 用 Cosmos-Reason2 backbone，prompt 接 system token <|im_start|>user\n<task>\n<|im_end|>。
  • π0.5 / SmolVLA 用 PaliGemma / SigLIP 文本 tower 直接 embed task string。
  • 建议 prompt 风格：动词短语 + 风格描述，例如： 
    fight  → "perform a boxing stance with quick jabs and hooks"
run    → "run forward at moderate pace, maintaining balance"
dance  → "perform a rhythmic dance with arm swings and steps"
jumps  → "execute a vertical jump with bent knees on landing"
变种 prompt 增强： 每 motion 写 3-5 个同义 prompt（"fight" / "box" / "spar" / "fighting stance"）， 随机抽样作 task — VLA 学到 language-level 鲁棒，不是单 string 过拟合。

4. 局限性与风险 Limitations & Risks

4.1 已知失败模式 Known failure modes

🔴 SigLIP @ 224 视觉瓶颈（参考 pi05-pytorch-expertonly-phase15-negative 项目记忆）
本项目橙子 picking 用 π0.5 SigLIP@224，因为橙子缩放后 ≤1 个 patch 导致 1.7% 成功率惨败。
人形 224 输入虽然全身可见，但 "fight stance" vs "dance pose" 单帧识别能力有限 — 缓解：上 video VLA（Cosmos-Reason2、Eagle2）吃 frame history，或用 proprio state 作 dominant cue。
🔴 Dynamic balance reproducibility
DeepMimic PPO 在 60Hz 闭环里学到精细的 balance correction。VLA 推理 10-30Hz、有 jitter、 flow matching 输出有噪 — student 极可能在 takeoff/landing/quick-pivot 摔。
缓解：(1) action chunking horizon=16 让 VLA 出短段；(2) inference 时 PD controller 内插到 60Hz； (3) eval 用 success rate 而非完美 trajectory match。
🟡 Distribution mismatch RL state-based → VLA visual-based
PPO obs 含 ref motion phase（teacher knows what phase to track），VLA 没这个。 VLA 必须从 RGB+proprio 自己推断 phase — 这是 imitation 路径上的关键差异。
缓解：训练时把 phase encoding 作 auxiliary loss 或不暴露给 student， 让 visual feature 主导，类似 GAIL/SQIL 范式。

对主稿的关键修正：

  1. GR00T 吃 LeRobot v2 + modality.json，不是 v3。Parquet 必须含 annotation.human.action.task_description 字段，meta/tasks.jsonl 放自然语言。 Source: GR00T data prep docs.

7.2 最终裁决 + 统一执行顺序 Verdict & Unified Order

裁决 / Verdict · 当前第一优先级不是铺 dance expert，而是先补 3 块缺失基建（G1 rollout recorder / 29-DoF modality.json / 第三人称 camera），跑激进 sanity 验证蒸馏管线通不通。 多 dance expert 是管线验证之后才做的事。
Biggest unknown is not "too few teachers" but whether the recorder/modality/camera/phase/student chain works at all. Feeding more experts into an unvalidated pipeline just over-feeds a broken chain.
  1. 补 3 块基建（P0 camera mount + P1b 29-DoF modality.json + P1a G1 rollout recorder）— ~1.5d
  2. 激进 sanity：10 ep × 2 motion（GPT-5.4 建议 fight + dance，prompt 区分度最强）→ go/pivot 判定
  3. 通了 → 加第 2 个 dance expert（必须 dance2，不同编舞）
  4. → 加第 3 个（dance1/dance2 不同 phrase，不是平移几秒）
  5. student 出现语义混淆 / average-motion → 再扩到 4-6 clips
  6. 全程开 prompt 侧多样化（最便宜杠杆，立刻用）

clip 选择优先级（GPT-5.4）：① 不同编舞(dance1 vs dance2) ＞ ② 同编舞不同 phrase ＞ ③ 同 phrase 不同 subject。 "先扩内容，再扩演法。"

对最初问题的终答 / Bottom line · 现在既不训长、也先别铺多 expert —— 先补基建跑 sanity。dance expert 组是 sanity 通过后的第 3 步。
