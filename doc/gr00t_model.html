1. 模型概述

GR00T N1.6 是 NVIDIA 发布的开源 视觉-语言-动作（Vision-Language-Action, VLA）基础模型， 目标是为通用人形机器人提供一个跨形态、跨任务的策略骨架。模型以多模态输入（图像 + 语言指令 + 本体状态）为条件， 通过扩散动作头（diffusion action head）输出连续动作序列。

  • 参数规模：3B（30 亿参数）
  • 权重：开源，HuggingFace nvidia/GR00T-N1.6-3B
  • 训练数据：1 万小时以上机器人数据，覆盖双臂、半人形、全人形多类形态
  • 定位：预训练 base 模型，可直接 zero-shot 部署部分任务，亦可在用户少量数据上 post-training 适配新形态/新任务

2. 网络架构

GR00T N1.6 采用视觉-语言基础模型 + 扩散变换器（DiT）动作头的双塔结构：

  • VLM 主干：从图像与语言中提取多模态上下文表征，支持开放词汇任务描述
  • 动作头：DiT（Diffusion Transformer），对连续动作序列做去噪生成； 默认推理步数为 4 步（denoising_steps=4），在精度与延迟之间取得平衡
  • 动作表示：N1.6 多数 embodiment 上预测相对动作块（state-relative action chunk）， 而非绝对关节角，更利于跨场景泛化
  • 动作 horizon：典型 16 步动作块，由客户端配置（--policy_action_horizon / action_horizon）

3. N1.6 相对 N1.5 的改进

  • 架构与数据双重升级，整体性能在主要 benchmark 上显著提升
  • 多数 embodiment 改用状态相对动作块，替代 N1.5 的绝对关节角 / 末端位姿
  • 预训练数据在 N1.5 的基础上新增数千小时遥操作数据，涵盖人形双臂与半人形平台
  • 跨形态泛化能力增强，新增 Unitree G1、Galaxea R1 Pro 等 embodiment 直接支持

为什么大部分 benchmark 用 MuJoCo？
GR00T 1.6 的 9 个官方 benchmark 中只有 BEHAVIOR（经 OmniGibson）真正运行在 Isaac Sim 上，其余 7 个都基于 MuJoCo（含 tabletop、loco-manipulation、LIBERO、SimplerEnv）。 原因是接触密集的操作类任务在 MuJoCo / robosuite 上接触动力学更稳、单 env CPU 仿真快，且 GR00T 训练数据的生成管线 MimicGen / DexMimicGen 早已建在 MuJoCo 之上。 Isaac Sim 的强项（GPU 千 env 并行 RL、RTX 高保真渲染、OpenUSD 大场景）则在本系列 manipulation 评测里收益不明显。

7. 使用流程

典型 post-training 流程（官方推荐）：

  1. 用户在目标机器人上采集（视频 + 状态 + 动作）三元组演示数据
  2. 把数据转成 HuggingFace LeRobot Dataset V2 schema
  3. 选择最接近的 embodiment tag（或使用 NEW_EMBODIMENT）配置数据 modality
  4. 使用仓库 scripts/ 下的 finetuning 入口在 base 模型上做少样本 post-training
  5. 将训练好的 checkpoint 通过 gr00t/eval/run_gr00t_server.py 部署为推理服务
  6. 客户端（仿真器或真机控制器）通过 ZMQ 协议把观测发到服务端，接收预测动作执行
Zero-shot 直接评测：对已内置的 embodiment（如 GR1、G1），可跳过第 1-4 步， 直接用 base checkpoint 在官方 benchmark 上 rollout（本项目即采用此方式验证 robocasa-gr1-tabletop）。

8. 本项目中的集成

本项目（isaaclab-experience）采用服务端 / 客户端解耦架构， 推理服务与仿真环境分别独立运行：

8.1 服务端管理（server/）

脚本作用
server/init_server.sh初始化机器：apt 依赖、uv、Isaac-GR00T 仓库、uv sync 预热
server/start_server.sh启动 GR00T 推理服务（绑定 0.0.0.0:5555），支持 GR00T_SIM_WRAPPER=1 开启 sim policy wrapper
server/status_server.sh查看运行状态
server/stop_server.sh停止服务
server/verify_server.shTCP + ZMQ 双层探活

8.2 演示脚本（scripts/）

脚本作用
scripts/check_start_gr00t.sh幂等启动服务（带 sim wrapper），等就绪 + ZMQ 握手 + 报告 GPU 显存
scripts/preview_gr00t_inference.sh在 robocasa GR1 tabletop 任务上跑一次 rollout，生成 mp4 并用 totem 全屏播放
scripts/realtime_gr00t_viewer.sh同样跑 rollout，但用 mujoco.viewer.launch_passive 弹出原生 viewer 实时显示
scripts/realtime_gr00t_viewer.pyrealtime 脚本的 Python 主体（在官方 env 之上叠加 ViewerWrapper，零修改 sim 逻辑）
Viewer 交互：scripts/realtime_gr00t_viewer.sh 弹出的 MuJoCo viewer 原生支持鼠标交互 —— 左键拖动旋转视角，右键拖动平移，滚轮缩放，Tab 切换内置摄像机，双击物体选中，H 显示完整快捷键面板。 跑完 rollout 后窗口会保持打开直到用户手动关闭。

8.3 推理调用示例

客户端通过 ZMQ 与服务通信，以下命令在 GR1 robocasa 桌面上跑 1 个 episode：

# 步骤 1：启动服务（带 sim policy wrapper）
bash scripts/check_start_gr00t.sh

# 步骤 2：跑一次推理 + 实时 viewer
bash scripts/realtime_gr00t_viewer.sh

# 也可切换其它高成功率任务
ENV_NAME=gr1_unified/PosttrainPnPNovelFromTrayToPlateSplitA_GR1ArmsAndWaistFourierHands_Env \
  bash scripts/realtime_gr00t_viewer.sh

8.4 服务接口约定

  • 传输：ZMQ REQ / REP，tcp://<host>:5555
  • 编码：msgpack（含 numpy 扩展）
  • 观测：扁平 key 格式（video.<camera>、state.<joint_group>、task 等）， 由服务端 Gr00tSimPolicyWrapper 解析为模型期望的嵌套字典
  • 动作：返回长度为 action_horizon 的动作块，客户端逐步执行
Embodiment 一致性提醒：当前服务以 --embodiment-tag GR1 启动， 适合 robocasa-gr1-tabletop benchmark。本仓库 LeIsaac/ 的 SO-101 任务属于另一 embodiment， 直接用 base 模型推理会因 obs/action 维度不匹配而失败；需先在 SO-101 demonstrations 上做 finetune。
