GR00T N1.5 / N1.6 / N1.7 多 release 环境分离

2026-05-24 — env drift 引发 N1.6 cached HF code 与 transformers 4.57.3 不兼容；以 submodule + 独立 venv pattern 修复

Multi-release env split for GR00T: when shared venv hits transformers ABI conflict, split into per-release submodule + venv. EN summary inline.

TL;DR

问题：N1.5/N1.6/N1.7 三个 release 的 HF cached transformers_modules 各自针对不同 transformers 版本写的。共用一个 venv → 升级 transformers 满足 N1.7 时破坏 N1.6 cached code (4 个 ImportError/AttributeError 接连出现)。
解法：每个 release 一个 git submodule + 一个独立 venv，server_kind=gr00t-n{15,16,17} 路由到对应 venv。
额外修复：n1.7-release-2 的 Gr00tSimPolicyWrapper 严格 validate obs key（flat video.front not nested），baselines.tsv 切到 gr00t policy_type（用 flat-wire client class）。
验证：N1.7 1-round = 3/3 oranges 51.9s 100% success ✅

EN: Three GR00T HF model cards each have their own cached transformers_modules tied to a specific transformers version. A single shared venv breaks as soon as any release demands a different transformers. Fix: per-release submodule + venv, routed by server_kind.

3. 触发原因 — Why we had to split

当时（2026-05-24 早上）整个 GR00T 系列共用 /home/david/work/Isaac-GR00T/.venv，transformers 在某次手工 pip install 中飘到 4.57.3。运行 N1.6 server 暴露 cached HF code 与新版 transformers ABI 不兼容，连续 4 个 ImportError/AttributeError：

EN: Cached HF code is frozen at model upload time. Bumping transformers for one release breaks the others — must isolate.

4. 第二个坑：n1.7-release-2 Gr00tSimPolicyWrapper 验证收紧

env split 后 N1.7 1-round 仍崩，server 返回 {"error": "Video key 'video.front' must be in observation"}。原因：

  • Gr00tSimPolicyWrapper.check_observation 期待 flat keys：video.front, state.single_arm at top level
  • LeIsaac 当前 Gr00t16ServicePolicyClient 发的是 nested：{"video": {"front": ...}, "state": {...}}
  • 之前外部 clone 的旧 commit wrapper 可能更宽松，所以 hi-space N1.7 之前 leaderboard rank 2 时能跑通

修法：baselines.tsv 4 个 GR00T row 的 policy_type 由 gr00tn1.6 改为 gr00t，dispatch 到 Gr00tServicePolicyClient（flat-wire 实现，含已维护的 GR00T_WRAP_OBSERVATION=1 envelope 切换 + 4 个 wire bug fix）。
